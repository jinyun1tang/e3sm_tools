E3SM · ELM · Crop carbon-balance diagnosis

Create a single-point simulation on Chrysalis

Use extracted land inputs with I1850GSWCNPPHSWFMCROP, the Intel compiler, and the original GSWP3 forcing streams.

Prepared September 10, 2026. This workflow is based on the supplied lnd_in, datm_in, mosart_in, and the inspected E3SM checkout. Commands are a template and have not been executed on Chrysalis.

Inputs · Create case · ELM settings · Forcing · Build and run · Validation

1. Prepare inputs and choose a case name

Run on Chrysalis using the same E3SM source version as the original simulation where possible. Replace all example paths and choose a unique CASENAME. The point retains every crop patch and topographic unit belonging to the selected grid cell.

Extracted filePurpose
domain_point.ncLand and DATM destination domain
surfdata_point.ncSurface properties, crop fractions, soil and topography
landuse_point.ncTransient crop/PFT fractions and harvest
initial_point.ncELM state with consistent subgrid relationships

The extraction tools and YAML instructions are in point_extract/README.md. Reuse full atmospheric and auxiliary forcing files initially. Parameter and snow lookup files remain unchanged.

This checkout uses ELM_USRDAT and ELM_USRDAT_NAME, not the older CLM_USRDAT names in some OLMT examples. The selected grid has a null routing grid; preserve do_rtm=.false..

2. Create the case

Use Bash for the commands below. Add --project YOUR_ALLOCATION to create_newcase if your account requires an explicit allocation.

E3SM_ROOT=/path/to/E3SM
CASE=/path/to/CASENAME
POINT_DATA=/path/to/extracted/point/files

cd "$E3SM_ROOT/cime/scripts"
./create_newcase \
  --case "$CASE" \
  --compset I1850GSWCNPPHSWFMCROP \
  --res ELM_USRDAT \
  --mach chrysalis \
  --compiler intel \
  --pecount 1

cd "$CASE"

CIME uses --mach; --machine belongs to other wrappers. One MPI task is suitable as an initial point configuration; the scheduler may still allocate a whole node.

3. Set domain, dates, and forcing years

./xmlchange ELM_USRDAT_NAME=1x1pt_crop
./xmlchange ATM_DOMAIN_PATH="$POINT_DATA"
./xmlchange LND_DOMAIN_PATH="$POINT_DATA"
./xmlchange ATM_DOMAIN_FILE=domain_point.nc
./xmlchange LND_DOMAIN_FILE=domain_point.nc

./xmlchange RUN_TYPE=startup
./xmlchange CONTINUE_RUN=FALSE
./xmlchange RUN_STARTDATE=0001-01-03

./xmlchange DATM_CLMNCEP_YR_START=1901
./xmlchange DATM_CLMNCEP_YR_END=1920
./xmlchange DATM_CLMNCEP_YR_ALIGN=1

./xmlchange ATM_NCPL=48
./xmlchange STOP_OPTION=ndays,STOP_N=5
./xmlchange REST_OPTION=ndays,REST_N=1
./xmlchange DOUT_S=FALSE

January 3, year 1 matches the supplied restart filename. Verify the actual initial-state timestamp, including time of day. Keep the original calendar. Model year 1 is aligned with forcing year 1901; five days is only an initial smoke run.

This is a new startup initialized from ELM state. It is not an exact continuation of the complete coupled simulation, which would also require compatible component and coupler restart state.

4. Configure user_nl_elm

Start with the original case's user_nl_elm when available. Set the four point paths to absolute paths:

fsurdat = '/absolute/path/to/surfdata_point.nc'
finidat = '/absolute/path/to/initial_point.nc'
flanduse_timeseries = '/absolute/path/to/landuse_point.nc'

Preserve the original crop, soil, irrigation, and transient settings:

dtime = 1800
maxpatch_pft = 51
create_crop_landunit = .true.
use_crop = .true.
irrigate = .true.
tw_irr = .true.
do_harvest = .true.
do_transient_crops = .true.
do_transient_pfts = .true.
use_hydrstress = .true.
use_lch4 = .true.
use_vertsoilc = .true.
use_dynroot = .false.
spinup_state = 0
do_budgets = .true.

Keep the original paramfile, fsoilordercon, fsnowaging, and fsnowoptics paths, plus other original overrides such as nutrient competition, soil decomposition, and topographic options. The excerpt above is not a replacement for every original setting.

Retain the original auxiliary stream file paths and configuration:

5. Preserve inactive MOSART

In user_nl_mosart, preserve the original overrides, including:

do_rtm = .false.

The inspected RtmMod.F90 returns from routing initialization when this is false. No point river network or reservoir dataset needs to be created. Keep ELM's original two-way irrigation configuration, and verify imported supply/deficit values rather than changing irrigation mode to get the case running.

6. Set up and inspect DATM

./case.setup
./preview_namelists

Inspect CaseDocs/datm_in and CaseDocs/lnd_in. DATM's domainfile must be the point destination domain. Keep datamode='CLMNCEP', as in the original configuration.

All five originally use mapalgo='bilinear', fillalgo='nn', mapmask='nomask', fillmask='nomask', taxmode='cycle', and dtlimit=1.5. Preserve their order and settings.

If generated source streams differ from the original run, copy the five original stream definitions into the case with the user_ prefix. For example:

cp /path/to/original/datm.streams.txt.CLMGSWP3v1.Solar \
   "$CASE/user_datm.streams.txt.CLMGSWP3v1.Solar"

Repeat for Precip, TPQW, aerosols, and topography. Ensure any relative source paths still resolve. Rerun ./preview_namelists. If namelist stream settings also differ, preserve the original settings through user_nl_datm and verify the generated result.

Keep each stream's original source domain and source data together. Only the DATM destination is the extracted land point. Replacing a global source domain with a point domain while keeping global data is inconsistent.

7. Check inputs, build, and submit

./check_input_data
./case.build
./case.submit
./xmlquery RUNDIR

Resolve missing inputs before building. Check the generated batch script and allocation settings before submitting. Inspect the ELM log in the reported run directory for initialization warnings, consistency failures, and carbon-balance diagnostics.

8. Validate the reproduction

  • Confirm the point's latitude, longitude, land fractions, crop/PFT composition, and topographic units.
  • Compare initialized crop pools and weights with the source cell, especially leafc_xfer, grainc, cropseedc_deficit, and column prod1c.
  • Confirm forcing calendar, year alignment, weather values, auxiliary inputs, and parameter files.
  • Check that MOSART remains inactive and irrigation supply/deficit behavior matches the original run.
  • Run through the planting or harvest event that triggered the original error. A successful five-day smoke run does not prove the event is reproduced.
  • Investigate initial-condition consistency failures before disabling checks; extraction preserves values but does not guarantee the new case builds an identical subgrid structure.

Actual executable behavior depends on the source version used on Chrysalis.
